# Claude에게 일을 맡기는 방식

사람이 매 단계 지켜보던 일을 설정과 검사로 옮긴 것입니다. 무엇이 어디에 있는지와,
아직 사람이 해야 하는 일을 적어 둡니다.

## 무엇이 무엇을 맡는가

| 사람이 하던 일 | 지금 맡는 것 | 파일 |
|---|---|---|
| 방향 잡아 주기 | 코드만 봐서는 알 수 없는 것만 적은 메모 | `CLAUDE.md` |
| 명령마다 승인 | 항상 허용할 명령, 물어볼 명령 | `.claude/settings.json`의 `allow`, `ask` |
| 안 된다고 막기 | 되돌릴 수 없는 명령 금지 | `.claude/settings.json`의 `deny` |
| 끝났는지 확인 | 편집할 때마다 테스트, 끝내기 전에 사이트 검사 | `scripts/hooks/`, `scripts/check.sh` |
| 병합 전 확인 | PR마다 같은 검사 | `.github/workflows/ci.yml` |
| 자동 수집이 깨진 사이트를 올리는 것 막기 | 커밋 전에 테스트와 사이트 검사 | `.github/workflows/update.yml` |

금지와 승인의 기준은 "틀렸을 때 되돌릴 수 있는가"입니다. 강제 푸시와 `git reset --hard`는 금지하고,
main 푸시와 PR 병합은 물어봅니다. 운영 사이트가 바로 바뀌기 때문입니다.

## 일을 맡길 때 적을 것

```
[할 일] 무엇을 바꾸는지 한두 문장.
[완료 기준] 무엇이 보이면 끝난 것인지. 예: /stocks/nvda/에 보유 큰손 표가 나온다.
[검사] bash scripts/check.sh 통과. 화면이 바뀌면 캡처를 붙인다.
[범위] rebuild 브랜치에서 작업하고 PR을 연다. main 반영은 묻는다.
[증거] 실행한 명령과 출력, 바뀐 화면의 캡처를 보여 준다.
```

"테스트 통과"라는 말만으로는 알 수 있는 것이 적습니다. 출력과 캡처를 달라고 하세요.

## 직접 켜야 하는 것

파일로는 켤 수 없어서 화면에서 해야 합니다.

- [ ] GitHub → Settings → Branches: `main`에 "Require status checks to pass"를 켜고 CI의 `check`를 지정
- [ ] GitHub → Settings → General: "Allow auto-merge" (검사가 통과하면 PR이 저절로 병합되게 하려면)
- [ ] (선택) Claude 클라우드 환경의 네트워크 설정에서 `sec.gov`, `api.openfigi.com` 접근을 허용할 수 있으면 수집도 그 환경에서 돌려 볼 수 있음. 지금은 막혀 있어 수집은 GitHub Actions에서만 돈다
- [ ] Google Search Console, 네이버 서치어드바이저, Bing에 사이트 등록과 `sitemap.xml` 제출
